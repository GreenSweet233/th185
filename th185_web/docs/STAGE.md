## 1. `.std` 是什么

`th185.dat` 里有 **9 个 `.std`**，与调研的「9 个场景」完全对应：

| 文件 | 波次数 | 组数 | 实体数 |
|---|---|---|---|
| `world01t.std` | 7 | 7 | 88 |
| `world01.std` | 4 | 10 | 24 |
| `world02.std` | 9 | 9 | 88 |
| `world03.std` | 7 | 43 | 68 |
| `world04.std` | 4 | 35 | 52 |
| `world05.std` | 3 | 14 | 12 |
| `world06.std` | 5 | 23 | 37 |
| `world07.std` | 1 | 8 | 5 |
| `world08.std` | 1 | 8 | 5 |

**重要区分**：`.std` **不是**波次模板池。
111 项的波次名表（VA `0x4B5D50`，见 `docs/WAVES.md`）是全局表；
`.std` 存的是**每个场景自己的布局**。

## 2. 文件结构

### 2.1 头部（16 字节）

```c
struct StdHeader {
    uint16 wave_count;      // +0x00  波次槽位数
    uint16 group_count;     // +0x02  实体组数
    uint32 entity_offset;   // +0x04  实体表绝对偏移
    uint32 unknown;         // +0x08  观察到 500..2704，语义待定
    uint32 reserved;        // +0x0C  恒为 0
};
// +0x10: char anm_name[];  NUL 结尾，如 "world01t.anm"
```

### 2.2 波次偏移表（`+0x90`）

`wave_count` 个 `uint32`，指向各波次项的绝对偏移。

`world01t.std` 实测：`172, 232, 292, 352, 412, 472, 532`

**步长恒为 60 字节。**

### 2.3 波次项（60 字节）

```c
struct WaveEntry {
    uint32 marker;    // +0x00  0x00010000 / 0x00060001 / 0x00020004 ...
                      //        低 16 位像是某个索引
    uint8  pad[0x0C];
    float  f1;        // +0x10  256.0 / 300.0
    float  f2;        // +0x14  256.0 / 1024.0
    float  f3;        // +0x18  256.0 / 512.0
    uint32 flags;     // +0x1C  0x001C0000
    uint32 slot_id;   // +0x20  槽位 id（不是序号，见下）
    uint8  pad2[0x0C];
    float  g1, g2;    // +0x30 与 f1/f2 同值
    uint32 marker2;   // +0x38  0x0004FFFF
};
```

#### 关于 `+0x20` 字段

**它不是序号。** 实测序列：

| 场景 | `+0x20` 序列 |
|---|---|
| `world01t` | `0,1,2,3,4,5,6` |
| `world03` | `0,1,2,2,2,9,10` |
| `world04` | `1,0,5,4` |
| `world05` | `0,5,6` |

同一个值会重复出现，且不连续，说明它是**波次类型/槽位 id**，
可能指向 111 项波次名表的某个子集。

### 2.4 实体项（16 字节）

```c
struct EntityEntry {
    uint32 kind;   // 高字节 0x01，如 0x01000000
                   //   bits 16..23 = type
                   //   bits  0..15 = index
    float  x, y, z;
};
```

9 个场景合计 **379 个实体**。

坐标范围实测：`-256` 到 `4352`（`world04` / `world06` 有 `y=4352` 的大值）。

## 6. 指令流（本轮新解出）

### 6.1 位置

头部 `+0x08` 的 `unknown` 字段指向指令流的**前导 4 字节**，
实际指令从 `unknown + 4` 开始。

### 6.2 格式

```c
struct Command {
    uint16 id;     // 指令类型
    uint16 size;   // 含头部的总长度
    uint8  payload[size - 4];
};
// 遇到 id==0 && size==0 结束
```

### 6.3 决定性验证

**9 个场景的指令流都恰好剩余 16 字节**（固定的尾部数据）：

```
world01t.std   38 条, 结束 0x0B4C/2908, 剩余 16
world01.std    40 条, 结束 0x0724/1844, 剩余 16
world02.std    47 条, 结束 0x0CA0/3248, 剩余 16
world03.std    21 条, 结束 0x0C54/3172, 剩余 16
world04.std    16 条, 结束 0x09A4/2484, 剩余 16
world05.std    49 条, 结束 0x0798/1960, 剩余 16
world06.std    63 条, 结束 0x0BEC/3068, 剩余 16
world07.std   117 条, 结束 0x0BAC/3004, 剩余 16
world08.std   117 条, 结束 0x0BAC/3004, 剩余 16
```

**9 个全部剩余 16 字节，不可能是巧合。** 这证明格式完全正确。

### 6.5 初步语义推测

| id | 推测 | 依据 |
|---|---|---|
| 2 | 实体放置 | payload 含 3 个 float 坐标 + 1 个 u32 |
| 3 | 实体放置（带参数） | 前 8 字节是 id/param，后接坐标 |
| 5 / 9 | 带 id 的实体 | 前 4 字节是递增 id（`0x154`, `0x2e4`） |
| 1 | 波次边界标记 | 3 个 u32 递增（`0x11c`, `0x438`, `0x5c8`） |
| 14 | 空操作/延时 | payload 全零 |
| 6 | 初始化 | 含 `0x3f800000` = 1.0 |
| 7 | 设置参数 | 含 `0x3f20d97c` ≈ 0.628 |

## 7. ★ 新发现：28 字节实体组表（本轮）

### 7.1 上一轮漏掉的段

上一轮我把 `.std` 的波次项之后直接当作实体表，但这只对 4/9 的文件成立：

| 文件 | 末波次结束 | 实体表开始 | 间隔 |
|---|---|---|---|
| `world01t` | 592 | 592 | **0** |
| `world01` | 568 | 568 | **0** |
| `world02` | 720 | 720 | **0** |
| `world03` | 1600 | 1600 | **0** |
| `world04` | 848 | 1268 | **420** |
| `world05` | 504 | 644 | **140** |
| `world06` | 772 | 968 | **196** |
| `world07` | 208 | 404 | **196** |
| `world08` | 208 | 404 | **196** |

**所有间隔都是 28 的倍数**（420/28=15、140/28=5、196/28=7）——这是决定性线索。

### 7.2 结构

```c
struct StageGroup {      // 28 bytes
    uint32 type;         // 观察值 0..9（实体类型枚举）
    float  x, y;         // 坐标
    uint32 reserved;     // 恒 0
    float  size_a;       // 观察值 16.0
    float  size_b;       // 观察值 512.0
    uint32 marker;       // 0x001C0000，末项为 0x0004FFFF
};
```

### 7.3 项数分布

| 文件 | 项数 | `type` 值 |
|---|---|---|
| `world01t`..`world03` | **0** | — |
| `world04` | **15** | `3,4,5,6,7,8,9` |
| `world05` | **5** | `6` |
| `world06` | **7** | `7` |
| `world07` / `world08` | **7** | `0,1` |
| **合计** | **41** | |

### 7.4 坐标是环形排列

`world04` 前 7 项：

| # | 坐标 | 半径 | 角度 |
|---|---|---|---|
| 0 | (101.65, 5.65) | 20.74 | -142.3° |
| 1 | (115.30, 0.00) | 18.55 | -98.5° |
| 2 | (128.95, 5.65) | 16.73 | -49.4° |
| 3 | (134.60, 19.30) | 16.57 | 3.3° |

**角度间隔约 48°**（360/7.5），半径 16.4~20.7 略有起伏。

这是**环形敌人编队**——7 个敌人绕一圈。


### 7.7 教训：上一轮的教训只用了一半

上一轮我学到「变长段可能不止一个」，并写进了文档。
**但本轮检查 `.std` 时，我最初仍然假设波次项后直接是实体表**——
直到交叉校验报出「4/9 文件间隔非 0」才发现。

**这说明「知道教训」不等于「会应用教训」。**
可靠的做法是**机械化检查**：对每一对相邻段，都算一次间隔，
看是否所有样本一致；若不一致，就是变长段。
